# BH4TDV-RF 板卡支持说明

## 1. 定位

BH4TDV-RF 是 BI4UMD 显示主板加“NRL 伴侣扩展板”的独立固件目标。它保留原
BI4UMD 的 ILI9341 触摸屏、ES8311 音频、TF 卡、电池检测和 GPS 功能，新增：

- SR-110U UHF 1 W 模拟语音/数传模块；
- PCA9555 16 位 I2C GPIO 扩展器；
- 一个独立 PTT 键、三向键和两个功能键；
- 射频模块电源、PTT、SQL 和高低功率控制；
- 后续 I2C 传感器扩展能力。

固件板型名为 `bh4tdv_rf`，板级宏为 `NRL_BOARD_BH4TDV_RF`。原 `bi4umd`
目标及其触屏交互保持不变。

## 2. ESP32-S3 引脚

| 功能 | GPIO | 说明 |
| --- | ---: | --- |
| GPS UART RX | 2 | 延续已验证的 UMD GPS 接法 |
| GPS UART TX | 3 | 延续已验证的 UMD GPS 接法 |
| SR-110U UART RX | 44 | 接模块 TXD |
| SR-110U UART TX | 43 | 接模块 RXD |
| PCA9555 INT | 14 | 低有效，使用 ESP32 内部上拉 |
| F1/PTT 键 | 21 | 低有效，使用 ESP32 内部上拉 |
| I2C SCL | 15 | 与触摸、ES8311 共用 |
| I2C SDA | 16 | 与触摸、ES8311 共用 |

显示、触摸、I2S、TF 卡、功放使能和电池 ADC 引脚与 BI4UMD 相同。

## 3. PCA9555

地址脚 A0/A1/A2 全部接地，7 位 I2C 地址为 `0x20`。

### 3.1 端口定义

| 端口 | 信号 | 方向 | 有效电平 |
| --- | --- | --- | --- |
| P0.0 | F2 | 输入 | 0=按下 |
| P0.1 | F3 | 输入 | 0=按下 |
| P0.6 | GPS_EN | 输出 | 1=GPS 上电 |
| P1.0 | IO_EXT_01 | 输入 | 预留，高阻 |
| P1.1 | PD | 输出 | 1=SR-110U 开机，0=关机 |
| P1.2 | PTT1 | 输出 | 1=发射，0=接收；板上 MOS 管转换为模块 PTT 低有效 |
| P1.3 | SQL | 输入 | 0=收到射频信号，1=无信号 |
| P1.4 | HL_IN | 输出 | 1=低功率，0=高功率；板上三极管实现接地/悬空 |
| P1.5 | KEY_C | 输入 | 三向键 PRESS，0=按下 |
| P1.6 | KEY_B | 输入 | 三向键 UP，0=按下 |
| P1.7 | KEY_A | 输入 | 三向键 DOWN，0=按下 |

方向寄存器：

- Configuration Port 0：`0xBF`；
- Configuration Port 1：`0xE9`。

### 3.2 安全初始化

PCA9555 上电后全部端口是输入，输出锁存器默认是高。为避免复位或启动时误发射，
初始化必须严格执行：

1. 探测地址 `0x20`；
2. 先写 Output Port 0；默认 `GPS_EN=0`；
3. 再写 Output Port 1；默认 `PD=0`、`PTT1=0`、`HL_IN=1`（低功率）；
4. 最后写两个 Configuration 寄存器；
5. 清读两个 Input Port；
6. 业务层要求开机时才置 `PD=1`，等待至少 500 ms 后访问 SR-110U 串口。

任意 I2C 错误都必须保持或恢复 `PTT1=0`。PCA9555 INT 用于降低轮询延迟，软件仍以
周期读取作为丢中断兜底。

## 4. SR-110U

### 4.1 电气和时序

- UART：9600 bit/s、8N1、无流控；
- 串口接口电平：3 V，ESP32-S3 3.3 V IO 直接连接；
- PD：1=开机，0=关机；
- PTT：模块脚 0=发射、1=接收；板上转换后软件 PTT1 为 1=发射；
- SQL：0=有接收信号；
- H/L：模块脚接地为低功率、悬空为高功率，严禁直接加高电平；
- 模块开机后等待至少 500 ms 才发送命令；
- 发射期间不发送参数设置命令。

首次连接使用 `AT+DMOCONT` 和 `AT+DMOVERQ` 验证模块。参数设置优先使用精简指令
集 `AT+DMOGRP`、`AT+DMOVOL`、`AT+DMOFUN`、`AT+DMOSAV` 和
`AT+DMORSSI`。H/L 硬件脚和 `DMOGRP Flag1` 必须保持一致。

SR-110U 手册的新旧指令集对 RFV/TFV 的文字定义不一致。固件按精简指令集处理：
RFV 为接收频率、TFV 为发射频率；首件必须用异频收发测试确认。

### 4.2 音频

- SR-110U AF_OUT 标称约 150-300 mVrms，经电位器和隔直电容进入 BI4UMD ADC；
- SR-110U MIC_IN 调制灵敏度约 5-12 mVrms，由 BI4UMD DAC 经电位器衰减后输入；
- 首件用 1 kHz 正弦波标定收发增益，确保不削顶并记录两个电位器的出厂位置。

### 4.3 供电注意

SR-110U 推荐 3.6-4.2 V、供电能力至少 1 A，高功率发射典型电流约 650 mA。
扩展板当前从 5V_MAIN 供电，处于模块标称最大工作电压边界。硬件定版前必须测试
5V_MAIN 的最高电压、纹波、高功率发射跌落和连续发射温升。

## 5. 实体键交互

按键事件统一为 `Press`、`Release`、`ShortPress`、`LongPress` 和 `Repeat`。PCA9555
读取和消抖在板级驱动中完成，LVGL 只在显示任务中消费事件。

| 按键 | 固定角色 |
| --- | --- |
| F1 | PTT，按住有效、松开停止；不参与菜单确认 |
| KEY_UP | 上移或增加，支持长按重复 |
| KEY_DOWN | 下移或减少，支持长按重复 |
| KEY_PRESS | 确认、进入、播放/暂停 |
| F2 | 左软键 |
| F3 | 右软键 |

第一阶段页面映射：

| 页面 | UP/DOWN | PRESS | F2 | F3 |
| --- | --- | --- | --- | --- |
| 射频主页 | 音量 -/+ | 主菜单 | 音乐 | 设置 |
| 主菜单/列表 | 上下选择 | 确认 | 返回 | 主页 |
| 音乐播放 | 音量 -/+ | 播放/暂停 | 上一首 | 下一首 |
| 音乐列表 | 上下选择 | 播放 | 返回 | 刷新 |
| 设置/调试 | 上下选择或调整 | 确认 | 返回 | 主页 |

BH4TDV-RF 主页移除音乐、设置和屏幕 PTT 三个重复触摸按钮，通用菜单也不再绘制
UP/DOWN/OK 导航按钮，主页底部改为实体键提示。音乐和设置页现阶段保留触摸控件作为
调试与兼容入口，实体键可完成常用操作；CW、地图和 SSTV 继续保留其必要的专用触摸区域。

## 6. 射频桥接状态

- 网络/FMO 下行语音开始时拉起 SR-110U PTT，所有下行源都空闲后释放；
- SR-110U SQL 为低时允许射频接收音频进入上行链路；
- F1 保持现有 UMD 本机 PTT 语义，不直接绕过音频路由强制射频发射；
- 参数写入与射频发射互斥；
- 关机、OTA、重启和驱动错误路径都必须先释放射频 PTT。

## 7. 验收

1. 上电、复位和 OTA 重启期间 SR-110U 不产生载波；
2. I2C 扫描可见 `0x20`，触摸和 ES8311 工作正常；
3. 六个实体键短按、长按和连发无误触；
4. GPS 功能与原 BI4UMD 一致；
5. `AT+DMOCONT`、版本查询和 RSSI 查询正常；
6. SQL 低有效逻辑正确，网络下行能自动控制射频 PTT；
7. 高低功率脚和串口配置一致；
8. 1 kHz 音频双向测试无削顶、无明显底噪；
9. 高功率连续发射时电源不复位、不过热；
10. `bi4umd`、`bh4tdv` 与 `bh4tdv_rf` 三个目标均能独立构建。

## 8. 环境传感器与电子罗盘

扩展板传感器确定为 I2C 接口的 BMP280 + AHT20 组合模块、QMC5883L 电子罗盘和 BH1750
光照传感器，使用原理图中的 `VCC/SDA/SCL/GND` 接口。该接口与触摸、ES8311 和 PCA9555
共用 GPIO16/GPIO15。

| 器件 | 7 位地址 | 当前结论 |
| --- | --- | --- |
| BMP280 | `0x76`（SDO=0） | 与现有器件不冲突；板级地址固定，不探测 `0x77` |
| AHT20 | 固定 `0x38` | 与 BH4TDV-RF 触摸控制器 `0x38` 冲突，当前硬件不能同时使用 |
| QMC5883L | `0x0D` | 与现有器件不冲突，可直接接入共享 I2C 总线 |
| BH1750 | `0x23`（ADDR=0） | 与现有器件不冲突；资料中的 `0x46` 是包含写方向位的 8 位地址 |

AHT20 的地址不可配置。两个 `0x38` 器件直接并接时会同时应答，读数据可能发生线与冲突，
而且发给其中一个器件的命令也会被另一个器件接收；任务锁、分时轮询或修改驱动均不能解决。
在硬件方案确定前，固件不得向共享总线上的 AHT20 发送初始化或测量命令。

可选解决方案按推荐顺序为：

1. 将 AHT20 改为不同地址的温湿度传感器，例如地址为 `0x44/0x45` 的 SHT30；
2. 在扩展板增加 I2C 多路复用器，将触摸和 AHT20 放在不同通道；
3. 将传感器改接 ESP32-S3 的另一组可用 GPIO，建立独立 I2C 总线；
4. 如果产品确认完全不需要触摸，则在 BH4TDV-RF 固件中禁用触摸，保留 AHT20。

当前固件已经提供 BMP280 温度/气压、BH1750 照度，以及 QMC5883L 三轴磁场强度和未校准航向角
采集，并包含超时校验、有效值缓存和屏幕状态显示。环境及照度数据采样周期为 2 秒、罗盘更新周期
为 100 ms。BMP280 的 SDO 已确定接地，板级宏
`NRL_BMP280_I2C_ADDR` 固定为 `0x76`；首件还需确认传感器模块供电电压及模块上拉电阻值。

屏幕从“设置 -> 传感器”进入，显示温度、气压、湿度状态、照度、航向和三轴磁场强度；实体键在
设置页按 `CONFIRM/F2` 进入传感器页，传感器页按 `F2` 返回设置、按 `F3` 返回主页。Web 首页增加
“传感器”入口，页面地址为 `/sensors`，每 2 秒刷新；`/sensors/status` 提供 JSON 数据接口，
无效或尚未采集到的数据返回 `null`。AHT20 地址冲突解除前，屏幕和 Web 均明确显示冲突状态，
不生成虚假的湿度读数。

BH1750 的板级宏使用 ESP-IDF 所需的 7 位地址 `NRL_BH1750_I2C_ADDR=0x23`。对应总线上的
8 位写/读地址分别是 `0x46/0x47`；不得把 `0x46` 直接传给 ESP-IDF 的设备地址字段。若首件
ADDR 引脚实际为高电平，则应将板级地址改为 `0x5C`。

QMC5883L 的航向角必须经过硬铁偏移与软铁比例校准；未配备加速度计时只能提供水平放置条件下的
二维航向，设备倾斜后不能进行倾斜补偿。固件需要保存 X/Y/Z 零偏和比例系数，并允许从屏幕菜单
进入“旋转设备一周”的校准流程。首件应读取芯片 ID 寄存器并核对实装芯片，避免将兼容模块误按
HMC5883L 的地址和寄存器协议驱动。PCB 定版资料还必须标明 QMC5883L 的 X/Y 轴相对设备顶部和
天线方向，否则固件无法确定航向角的轴交换、正负号与零度方向。

## 9. I2C 设备探测与动态地址

BH4TDV-RF 固件在系统启动时自动扫描一次共享 I2C 总线，也可从屏幕的
`SETTINGS -> I2C SCAN` 页面按 `SCAN` 手工重新扫描，或从 Web 的 `/sensors` 页面
点击 `Scan 0x00-0xFF`。扫描覆盖全部 128 个 7 位地址
`0x00-0x7F`；页面同时显示对应的 8 位写/读地址，因此等价覆盖原始地址字节
`0x00-0xFF`。例如 PCA9555 的 7 位地址 `0x20` 会显示为写地址 `0x40`、读地址
`0x41`，避免把两种地址表示法混用。

屏幕和 Web 扫描结果均逐项显示 7 位地址、8 位写/读地址、识别出的型号和可读取的芯片标识；
`/sensors/status` JSON 同时提供结构化的 `i2c_revision` 与 `i2c_devices` 数据。
当前可识别并动态绑定 PCA9555、BMP280、QMC5883L 和 BH1750；手工扫描完成后
PCA9555 立即按新地址重新初始化，传感器任务检测到扫描版本变化后自动按识别地址
重新初始化。无可靠只读标识的器件会标为 `compatible` 或 `UNKNOWN`，不会仅凭应答
强行认定型号。

固定地址冲突会明确显示而不会冒险驱动：`0x38` 标为 `FT5x06/AHT20 CONFLICT`；
`0x23` 单独出现时标为 `BH1750/PCA9555 CONFLICT`。若同一次扫描已在其他地址确认
PCA9555，则可结合本板连接关系把 `0x23` 解析为 BH1750，并用该地址驱动光照传感器。

## 10. 后续资料与首件记录

  模块供电和 I2C 上拉的首件实测结果；

  已实现：固件默认 450.05000 MHz 收发同频、67.0 Hz CTCSS、SQL=2、音量=6、高功率，全部参数开放用户修改。

  已实现：参数持久化在 NVS namespace `radio`（key `sr110u`），配置入口为 Web `/radio` 页面和
  `AT+RADIO_*` 指令（串口 / `/api/at` / 网络远端共用）；开机和保存时通过 `AT+DMOGRP`、
  `AT+DMOFUN`、`AT+DMOVOL`、`AT+DMOSAV`、`AT+DMOVOX` 下发，H/L 硬件脚与 `DMOGRP Flag1` 联动。
- 首件实测的 5V_MAIN 电压/纹波、发射电流/温升、双向 1 kHz 音频电平及两个电位器位置；
- PCA9555 INT、五个扩展按键、SQL 与 GPS_EN 的首件逻辑分析仪记录。

在 AHT20 地址冲突解决前，固件只保留共享 I2C 总线与板级扩展能力，不初始化 AHT20，避免破坏
触摸操作或得到不可判定的传感器数据。
